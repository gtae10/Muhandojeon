# 개체 지문 촬영 가이드

> 목적: **같은 모델 두 개를 구분**하는 것. 브랜드나 모델을 알아보는 것이 아니라, 이 개체와
> 저 개체를 가르는 미세 텍스처(가죽 결의 무작위 패턴, 스티치의 미세한 간격 편차, 금속의 흠집
> 분포)를 기록한다. 그래서 "예쁜 제품 사진"이 아니라 **표면이 크게, 선명하게** 찍혀야 한다.

개체 지문용 공개 데이터셋은 없다. 팀원 소지품을 직접 촬영하는 것이 유일한 방법이므로 규약을
먼저 고정한다.

## 1. 디렉토리·파일명 규약

```
data/fingerprints/{asset_id}/{angle}_{index}.jpg
예) data/fingerprints/AS-0001/handle_01.jpg
    data/fingerprints/AS-0001/handle_02.jpg
    data/fingerprints/AS-0001/stitching_01.jpg
```

- `asset_id` 는 **시드의 개체 id 그대로**다(`fixtures/assets.json`, `AS-0001`~`AS-0018`).
  `GET /assets/{customer_id}` 응답이나 `make fixtures` 출력으로 확인한다.
  자릿수를 바꿔 적으면 매칭이 등록 이미지를 못 찾아 항상 유사도 0 이 된다.
- `angle` 은 아래 부위 표의 값을 소문자로 쓴다. `index` 는 2자리(01, 02, ...).
- 확장자는 `jpg` / `jpeg` / `png`. 규약을 어기면 등록 CLI 가 파일명 위반으로 걸러낸다.

## 2. 카테고리별 촬영 부위

| 카테고리 | 부위(angle) | 왜 이 부위인가 |
|---|---|---|
| BAG | `handle`, `corner`, `hardware`, `stitching` | 핸들·코너는 사용 흔적이 개체마다 다르게 남는다. 하드웨어 흠집 분포는 사실상 고유값이다 |
| SHOES | `sole`, `upper`, `stitching`, `edge` | 아웃솔 마모 패턴은 걷는 습관이 만든 지문이다. 웰트 스티치 간격 편차도 개체마다 다르다 |
| WATCH | `dial`, `bracelet`, `caseback` | 케이스백 각인·미세 스크래치, 브레이슬릿 링크 마모 |
| BELT | `buckle`, `edge`, `grain` | 버클 표면 흠집, 엣지 코트 균열, 가죽 결 |
| WALLET | `edge`, `stitching`, `interior` | 엣지 코트 벗겨짐 패턴, 내부 오염 |

부위당 **2장 이상**(각 2장 권장, 총 8장 내외)을 찍는다. 등록 CLI 가 부위 누락을 알려준다.

## 3. 촬영 조건

| 항목 | 기준 | 이유 |
|---|---|---|
| 거리 | 표면에서 **10~15cm**, 화면의 70% 이상이 대상 표면 | 결·스티치가 픽셀로 남아야 한다. 제품 전체가 보이면 너무 멀다 |
| 초점 | 표면에 수동 고정(스마트폰은 화면 탭 후 AE/AF 잠금) | 자동 초점이 배경으로 튀면 지문 정보가 사라진다 |
| 조명 | 창가 간접광 또는 확산광 2방향. **직사광·플래시 금지** | 정반사(하이라이트)가 생기면 그 부분 텍스처가 통째로 날아간다 |
| 각도 | 표면과 **수직(정면)**, 기울기 15° 이내 | 기울면 원근 왜곡으로 같은 개체도 다르게 보인다 |
| 배경 | 무광 단색(검정/회색 천) | 배경 패턴이 특징으로 오인되는 것을 막는다 |
| 해상도 | 짧은 변 **800px 이상** (원본 그대로 권장, 리사이즈 금지) | 미세 텍스처는 축소하면 소멸한다 |
| 손떨림 | 두 손 고정 또는 거치대, 셀프타이머 2초 | 흐림은 등록 단계에서 탈락 1순위다 |
| 후처리 | **없음.** 필터·자동보정·HDR 끄기 | 보정이 텍스처를 평탄화한다 |

같은 개체를 여러 번 등록할 때도 **거리와 각도를 비슷하게** 유지한다. 인증 시 촬영 조건이
등록 조건과 크게 다르면 같은 개체도 매칭에 실패한다.

## 4. 품질 기준 (등록 CLI 가 자동 판정)

| 지표 | 기준 | 측정 방법 |
|---|---|---|
| 해상도 | 짧은 변 ≥ 800px | 이미지 크기 |
| 선명도 | 라플라시안 분산 ≥ 60 | 그레이스케일에 3x3 라플라시안 적용 후 분산 |
| 밝기 | 평균 60~200 (0~255) | 그레이스케일 히스토그램 평균 |
| 대비 | 표준편차 ≥ 18 | 그레이스케일 표준편차 |
| 과노출 | 250 초과 픽셀 < 12% | 클리핑 비율 |

기준 미달 이미지는 DB에 `passed=false` 와 사유가 함께 기록되고 **재촬영 목록으로 출력**된다.
통과분이 하나라도 있으면 해당 개체의 `last_scanned_at` 이 갱신된다.

## 5. 등록 절차

```bash
# 등록 CLI 는 외부 데이터셋 보류와 함께 scripts/_deferred/ 로 빠져 있다(실행 경로 밖).
# 되살릴 때는 scripts/ 로 옮기고 아래처럼 쓴다.

# 0) 규약을 눈으로 확인 (샘플 이미지 8장 생성)
python -m scripts.register_fingerprint --make-sample AS-0001

# 1) 실제 촬영본을 data/fingerprints/{asset_id}/ 에 넣는다

# 2) 검증만 먼저 (DB 에 쓰지 않음)
python -m scripts.register_fingerprint data/fingerprints/AS-0001 --dry-run

# 3) 등록
python -m scripts.register_fingerprint data/fingerprints/AS-0001
python -m scripts.register_fingerprint --all      # 전체 개체 일괄
```

출력 예시

```
  [AS-0001] Aurelia Top Handle (BAG) — 이미지 11장
    ! badname.jpg: 파일명 규약 위반 ({angle}_{index}.jpg 형식)
    ok   handle_01.jpg      1200x1200 blur=24369.6 bright=129.0±36.7
    재촬영 handle_09.jpg    1200x1200 blur=   1.8 bright=129.5± 2.4
         → 흐림 (라플라시안 분산 1.8 < 60.0); 대비 부족 (표준편차 2.4 < 18.0)
    ! 부위 누락(통과분 기준): hardware
```

## 6. 역할 경계

- **통합/데모 담당(이 레포)**: 디렉토리 규약, 품질 검증, 경로 등록(`fingerprints` 테이블)까지.
- **백엔드 담당**: 등록된 경로를 읽어 임베딩을 추출하고 `POST /fingerprint/match` 를 구현한다.
  `fingerprints` 테이블의 `passed=true` 행만 쓰면 된다. 계약은 `docs/CONTRACTS.md` 참고.

```sql
-- 백엔드가 임베딩 대상으로 쓸 목록
select asset_id, angle, path from fingerprints where passed = 1 order by asset_id, angle, seq;
```

## 7. 데모용 최소 세트

발표에서 "같은 모델 두 개 구분"을 보여주려면 **동일 모델 2개체**가 필요하다.
팀원 소지품 중 같은 모델이 없으면, 같은 카테고리 2개체로 "서로 다른 개체는 매칭되지 않는다"를
보여주는 편이 안전하다. 촬영은 개체당 8장(부위 4 × 2장), 두 개체면 16장이면 충분하다.
